## CSV와 수집 기준

- `data/arts-sports-crawl-sources.csv`: 기존 입력 계약인 `college_name,department_name,url,parser_type`을 유지한 6개 출처. 모두 `SEJONG_STANDARD`이며 기존 fetcher가 학교 대표 홈페이지의 API 호출을 처리한다.
- `data/arts-sports-professors-reviewed.csv`: 교수별 출처, 페이지 유형, 수집값, 연구실명 유형, 검수 상태·일자·보정 사유. UTF-8이며 쉼표가 있는 필드는 CSV 인용 규칙을 따른다. 빈 칸은 미공개 값(NULL)이다.
- `data/arts-sports-research-field-links.csv`: 연구실별 분야 61행. 교수 이메일·출처·원문 소개·원문 조각·검수 분야명·카테고리 코드·분리 사유를 연결한다. 복수 카테고리 코드는 `|`로 구분한다.
- `data/arts-sports-research-field-categories.csv`: 고유 분야–카테고리 69행. 카테고리 이름·신규 여부·부모 코드·분류 근거를 기록한다. 이번에 사용하는 카테고리는 모두 최상위여서 부모 코드는 비어 있다.
- `data/arts-sports-text-review.csv`: 교수 18명의 오타·표기 검수 기록. 이메일·URL 원문과 보정값, 원문 소개와 검색용 분야명, 정리 사유를 구분한다.
- 공식 연구실 고유 명칭은 공개되지 않았다. 기존 승격 규칙에 따라 `교수명 교수님 연구실`을 생성하고 `name_source=GENERATED`, 모집 상태는 `UNKNOWN`으로 저장한다. 페이지의 연구실 위치를 연구실 이름으로 사용하지 않는다.
- 초빙·특임을 포함해 지정 URL에 나온 18명을 유지한다. 보조 학과 홈페이지에는 29명이 있으나 체육 4명·영화 7명은 지정 URL의 API 목록에 없다. 이는 공급 목록 차이이며 크롤러가 제외한 결과가 아니다. 보조 목록의 인원을 임의 추가하지 않았다.

## 오타·표기 검수 및 빈값

| 교수 | 원문 | 검수 결과 |
| --- | --- | --- |
| 최두영 | 이메일 `filmdoo@sejong.ac.kr ,` | 후행 공백·쉼표 제거 → `filmdoo@sejong.ac.kr` |
| 김형남 | 홈페이지 `https://www.sejong.ac.kr/kor/college/dance.do#none` | 현재 학과 화면을 가리키는 임시 링크 → NULL |

윤경희의 연구소개 끝 쉼표는 원문 그대로 보존했다. 김기훈·이은경·안연석의 연구소개는 원문이 비어 있어 NULL로 유지했다. 이메일은 18개 모두 서로 다르다. 홈페이지 5개는 각각 GET 200과 교수 이름을 확인했으며, 김나영의 기존 주소는 새 공식 홈페이지로 정상 이동한다.

이름·학과·직위·이메일·URL·연구소개·분야명의 철자와 표기를 검토했다. 위 형식 보정 외에 확정할 수 있는 어휘 오타는 발견하지 못했으며 전문용어를 추측하여 교정하거나 번역하지 않았다. 검색용 분야에서만 `첨단 패션 등`의 종결어와 최두영 소개의 목록 번호 `1)`, `2)`를 제거했다. 원문 소개는 변경하지 않았다.

## 연구분야 분리와 카테고리 매핑

구분자만으로 나누지 않고 의미 단위를 확인했다. 이기정의 영어 나열은 세 분야, 위정민의 소개는 여섯 분야, 강유원의 `체육원리 현상학`은 두 분야, 김형남의 소개는 세 분야로 수동 분리했다. `인공지능과 패션 디자인`, `예술/디자인사`, `뉴미디어 공연/영상콘텐츠` 같은 복합 표현은 유지했다. `제작`은 원문 이름을 보존하고 같은 분야로 재사용했다.

기존 `DESIGN_ARTS`, `HISTORY_CULTURE`, `POLICY_MANAGEMENT`, `AI_ML`, `HCI_XR`를 재사용했다. 기존 분류로 충분히 표현하기 어려운 음악·공연과 체육에는 최상위 카테고리 2개를 추가했다. 표시 순서는 현재 최댓값 다음으로 배정한다.

| 코드 | 이름 | 분류 범위 |
| --- | --- | --- |
| `MUSIC_PERFORMING_ARTS` | 음악·공연예술 | 기악·성악·음악문헌·무용·연기·공연예술 교육 |
| `SPORTS_PHYSICAL_EDUCATION` | 체육·스포츠 | 체육학·체육원리·스포츠철학·신체문화 |

분류는 검색을 위한 검수 판단이다. 분야명과 원문 문맥을 함께 보았고, 복수 의미가 명시된 분야는 여러 카테고리에 연결했다. `질적연구`는 해당 교수의 체육철학·인문학적 방법론 문맥을 근거로 `HISTORY_CULTURE`에 연결했다. 기존 전역 분야명·분류를 바꾸거나 삭제하지 않았다.

55개 분야 중 기존 `영화`와 그 `DESIGN_ARTS` 매핑을 재사용한다. 따라서 새로 추가되는 값은 분야 54개, 연구실 연결 61개, 카테고리 2개, 분야–카테고리 연결 68개다. 전체 카테고리는 52개에서 54개가 되며 V47의 로봇 하위 분류와 기존 부모 관계는 보존한다.

## 배포와 검증

`V48__import_reviewed_arts_sports_professors.sql`은 기존 V42 학과 ID를 찾아 출처와 누락된 교수·연구실·소속 연결을 추가한다. `V49__import_reviewed_arts_sports_research_fields.sql`은 교수 이메일·이름과 기존 활성 연구실을 찾아 분야·카테고리·연결을 추가한다. 숫자 ID를 고정하지 않는다. 기존 프로필, 수동 홈페이지, 공식 연구실명, 모집 상태, 연구분야 연결은 덮어쓰지 않는다. 신원·출처·연구실·카테고리 충돌은 본 테이블 기록 전에 차단한다.

격리된 H2 DB에서 기존 서비스로 6개 URL을 다시 수집해 18개 후보를 원문 스냅샷과 대조한 뒤 승인·승격했다. 교수·연구실 각 18개가 생성됐고 재승격 대상은 0개였으며, 기존 교수·연구실 각 303개는 그대로 유지됐다. 승격값과 검수 CSV 144개 필드도 모두 일치했다.

연구분야도 기존 추출·수동 분리·승격 서비스를 격리된 H2에서 실행했다. 자동 후보 52개에서 네 항목을 14개 자식 후보로 나누고, 원래 분리 대상 네 항목과 목록 번호 한 항목을 제외했다. 최종 61개를 승인·승격하여 분야 54개와 연구실 연결 61개를 생성했다. 재승격 대상은 0개였으며 기존 프로필·분야·연결·카테고리·검수 상태를 보존했다.

이 승격 DB에 V49를 적용해 카테고리 2개와 분류 연결 68개만 추가되는 것도 확인했다. 최종 연구실 연결 61개·분류 연결 69개가 검수본과 일치하고, 이미 승격된 분야·연결·후보 이력과 기존 카테고리·매핑은 그대로 유지됐다.

계약 테스트는 빈 DB 전체 마이그레이션, V47→V48 및 V48→V49 업그레이드, 검수 CSV와 저장값의 전수 일치, 기존 데이터 보존, 충돌 거절 및 SQL 재실행을 검증한다. 분야 테스트는 Hibernate 스키마 검증, 실제 JPA를 통한 카테고리 응답·연구실별 분야·카테고리 조회도 확인한다. 기존 수동값이 있는 업그레이드는 원문 CSV로 덮어쓰지 않고 보존 전후 값을 비교한다.

실행 결과: 교수·연구실 계약 16건(H2 8 + MySQL 8), 연구분야 계약 20건(H2 10 + MySQL 10)이 모두 통과했다. 별도로 실행한 전체 비Docker 회귀 테스트도 620건 통과했으며 실패·오류·스킵은 0건이다. 스킬 구조 검증도 통과했다.

```powershell
.\gradlew.bat test --tests '*ArtsSportsCatalogMigrationTest' --tests '*ArtsSportsCatalogMySqlMigrationTest'
.\gradlew.bat test --tests '*ArtsSportsResearchFieldMigrationTest' --tests '*ArtsSportsResearchFieldMySqlMigrationTest'
```

MySQL 테스트는 Docker의 MySQL 8.0.45 또는 전용 로컬 테스트 DB를 사용한다. 후자를 사용할 때 `SEBU_ARTS_SPORTS_TEST_MYSQL_URL`은 `jdbc:mysql://127.0.0.1:13377/sebu_arts_sports_test`로 제한되며, 별도 `SEBU_ARTS_SPORTS_TEST_MYSQL_USERNAME`·`SEBU_ARTS_SPORTS_TEST_MYSQL_PASSWORD`를 지정한다. 해당 테스트는 전용 DB를 초기화한다.

기존 수집·검수·승격 절차는 [교수 크롤링 안내](professor-crawling.md), [교수 승격 안내](professor-promotion.md), [연구분야 승격 안내](research-field-promotion.md)를 따른다. 운영 DB에 직접 실행하지 않았으며, 배포 시 Flyway가 V48·V49를 순서대로 적용한다. MySQL DDL은 트랜잭션으로 되돌릴 수 없으므로 충돌로 중단되면 부분 적용 여부를 확인한 뒤 재시도한다.
