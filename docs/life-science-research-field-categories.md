# 생명과학대 연구 분야 카테고리 연결

## 변경 범위

검수·승격을 거친 생명과학대 연구 분야 193개에 대한 247개 분야–카테고리 매핑을 추가한다.
분야 이름과 카테고리 코드로 연결하며 로컬 DB의 숫자 ID를 마이그레이션에 넣지 않는다.
기존 연구 분야, 카테고리, 연구실 연결, 후보의 검수·승격 이력은 변경하지 않는다.

기존 21개 카테고리 중 의료·AI·데이터·화학·수학·환경·로봇·산업 분류를 재사용한다.
기존 분류로 구분하기 어려운 다음 3개만 추가한다.

| 코드 | 표시 이름 | 표시 순서 | 추가 이유 |
| --- | --- | --- | --- |
| FOOD_NUTRITION | 식품·영양 | 22 | 식품 가공·안전·물성, 영양, 기능성·대체식품과 사료를 구분 |
| PLANT_AGRICULTURE | 식물·농업생명과학 | 23 | 식물 면역·육종·작물·농생명자원·스마트농업을 구분 |
| MOLECULAR_BIOTECH | 분자·세포생물학·생명공학 | 24 | 기초 세포·유전·효소·미생물·오믹스·생물공정을 의료 응용과 구분 |

분류 결과는 정답이 유일한 학문 분류가 아니라 검색을 위한 검수 기반 분류다.
명시적으로 여러 분야를 다루는 경우에만 복수 카테고리를 연결한다.
예를 들어 식품 인공지능은 식품·영양과 인공지능·기계학습에, 농업 로봇 및 AI는
식물·농업생명과학, 로봇·자율시스템, 인공지능·기계학습에 연결한다.

## 원문 문맥 처리

검수가 끝난 분야명을 이 작업에서 임의로 수정하거나 재분리하지 않는다.
짧거나 불완전한 명칭은 원문 연구실 설명을 함께 확인하여 분류했다.

- `철-`: 식물면역의 철·활성산소 의존성 페롭토시스 원문에서 분리된 조각으로 식물·농업에 연결한다.
- `식용`, `약용`, `사료용 곤충`: 곤충 활용 연구 문맥으로 분류한다.
- `environment and behavior`: 뇌·신경질환 연구 문맥으로 의료에 연결하며 환경·기후에 연결하지 않는다.
- `Hormonal Signaling`: 식물발달 문맥으로 분자·세포 및 식물·농업에 연결한다.
- `분자 네트워킹`: 천연물 분석기술로 화학·소재에 연결하며 통신·네트워크에 연결하지 않는다.
- `기능성 소재 개발`: 식물과 곤충 연구실에서 공유하므로 두 원문 문맥을 고려한다.
- `기능성 제품개발 연구`: 종양면역·감염면역·신약개발 문맥으로 의료에 연결한다.

이와 같은 명칭 자체의 개선은 별도 재검수 대상으로 남긴다. 향후 이름을 수정하면
승격 서비스와 후속 매핑 마이그레이션을 통해 변경된 이름의 연결도 확인해야 한다.

## 적용 방식

1. 교수·연구실 승격과 연구 분야 검수·승격을 먼저 완료한다.
2. V35는 기존 테이블에 신규 카테고리 행만 추가한다.
3. V36은 임시 분류 참조표를 이용해 **이미 존재하는** 연구 분야만 연결한다.
4. 동일한 분야–카테고리 쌍은 추가하지 않고 기존 매핑을 보존한다.
5. 검증 SQL로 대상 미매핑과 동일 쌍 중복이 각각 0건인지 확인한다.

빈 DB에서도 전체 마이그레이션은 실행할 수 있지만 연구 분야를 임의 생성하지 않는다.
따라서 V36 적용 시 존재하지 않았던 분야가 나중에 승격되면 V36이 자동 재실행되지는 않는다.
이 경우 적용된 V36을 수정하거나 삭제하지 말고 **새 후속 버전**에서 매핑을 보완한다.
운영에서도 검수 데이터 반입·승격과 매핑 배포 순서를 맞춰야 한다.

`seed`는 여기서 로컬 테스트용 가짜 데이터가 아니라 배포할 검색 분류 기준 데이터를 의미한다.
개인 검수용 추출 파일, 교수 원문 덤프, DB 백업, 인증 정보는 Git에 포함하지 않는다.

## 검증

- `ResearchFieldCategoryQueryServiceTest`: 새 카테고리도 기존 API 결과에 포함되고 표시 순서를 유지한다.
- `LifeScienceResearchFieldCategoryMySqlMigrationTest`: 빈 DB 전체 적용, V34 업그레이드,
  기존 행·매핑 보존, 참조 전용 분야의 비생성, SQL 재실행과 중복 방지, Hibernate 스키마 검증.
- 기존 카테고리 마이그레이션 회귀 테스트는 V34까지의 역사적 기대값을 유지한다.
- `docs/sql/verify-life-science-research-field-categories.sql`: 로컬 적용 후 조회 전용 검증.

Docker가 있으면 MySQL 8.4 Testcontainers를 사용한다. Docker가 없는 개발 환경에서는
테스트를 위해 만든 전용 MySQL 인스턴스 `127.0.0.1:13316`의
`sebu_life_science_migration_test` DB만 `SEBU_TEST_MYSQL_URL`로 지정할 수 있다.
이 DB의 내용은 테스트 시작 시 초기화된다. 사용자 DB `3306/sebu`는 지정할 수 없다.

새 마이그레이션은 참조표 입력과 카테고리·매핑 INSERT만 수행한다.
기존 업무 테이블 ALTER/DELETE는 없으며 INSERT 동안 대상 고유 인덱스 잠금이 발생할 수 있다.
적용 전 백업하고 동시 후보 승격·카테고리 변경 작업을 중지한 상태에서 실행한다.
