# 객체지향 설계와 SRP 적용

- 작성일: 2026-08-13
- 작성한 Skill: `apply-oop-srp`

## 필수 원칙

- 관련 운영 코드와 테스트를 먼저 확인하고 기존 구조와 관례를 따른다.
- SRP를 클래스당 하나의 메서드가 아니라 하나의 변경 이유로 해석한다.
- HTTP 표현은 `api`, 유스케이스와 트랜잭션 조정은 `application`, 불변 조건과 상태 전이는 `domain`, 영속성은 Repository에 둔다.
- `api`에서 `application`, `application`에서 `domain`으로 향하는 의존성 방향을 유지한다.
- 변경 가능한 상태를 캡슐화하고 생성자 주입과 합성을 우선한다.
- 실제 책임 경계나 대체 구현이 있을 때만 타입과 Interface를 추가한다.
- 작은 작업마다 클래스를 만들거나 가상의 요구사항을 위한 추상화를 도입하지 않는다.
- 요청과 무관한 리팩터링과 계층 간 도메인 규칙 중복을 만들지 않는다.

## 검증

- 주요 동작, 실패 사례, 도메인 불변 조건을 테스트한다.
- 변경된 타입마다 하나의 명확한 변경 이유가 있는지 확인한다.
- 순환 의존성과 HTTP·영속성 세부 사항의 Domain 유출 여부를 확인한다.
